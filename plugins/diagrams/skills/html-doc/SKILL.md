# 交互式 HTML 文档

让读者先看懂核心观点，再通过操作图形理解关系、比较差异、探索原因。少写文字，把信息组织进图及其交互状态中。用户指定的内容、格式、技术栈和视觉风格优先。

## 内容取舍

- 先确定读者、要回答的问题和一句话核心观点；能从材料推断时直接推进。
- 为每个主要视图确定一个要传达的结论，以及支持它的最少证据。避免把原文逐段搬进网页。
- 默认仅保留结论、图中标签、必要单位和操作提示。删除重复解释、背景铺陈、装饰性口号与泛泛总结。
- 关键结论、适用边界及会改变结论的限制应直接可见；推导、例子、术语和来源按需展开。不能为了精简而歪曲原意。
- 不以任意字数或屏数代替判断。必要的解释保留，能用图表达的关系优先交给图。

## 信息分层

按下列层次安排信息，不要求机械地生成三个区块：

| 层次 | 初始可见内容 | 展开方式 |
| --- | --- | --- |
| 总览 | 一句话观点、主图、必要图例、清晰的探索入口 | 读者无需操作即可理解主旨 |
| 探索 | 当前选中对象的关系、比较结果或过程步骤 | 点击节点、切换方案、筛选、拖动滑块或单步推进 |
| 证据 | 局部解释、计算口径、示例、原始数据和来源 | 详情面板、局部展开或原文链接 |

- 默认状态应有意义：展示有代表性的情景或选择，而非空白画布和等待填写的表单。
- 围绕当前问题披露局部信息。切换对象时更新同一详情区，避免每次点击都累积新面板。
- 选中、展开和筛选状态必须可辨认；提供返回总览、关闭或重置入口。
- 不让读者逐个点击才能拼出核心结论，也不把长文拆进大量折叠框来假装精简。
- 文档较长时先给总览，再让读者进入主题；可按任务需要保留自然滚动和锚点导航。

## 用图表达关系

先选择关系，再选择图形；优先使用可随状态更新的 SVG、HTML/CSS 或合适的图表库。

| 信息关系 | 合适的表达 | 有意义的交互 |
| --- | --- | --- |
| 因果、依赖、架构 | 有方向和含义的节点连线图 | 选择节点，高亮上下游与相关路径 |
| 步骤、状态变化 | 流程图、时间轴或状态图 | 单步推进，同步展示当前状态和局部变化 |
| 方案比较、取舍 | 并列图、矩阵或同尺度图表 | 切换条件或方案，同步更新差异 |
| 数量、分布、趋势 | 条形图、折线图或散点图 | 筛选、选区、显示局部数值与参照 |
| 层级、组成 | 可展开树、分组图或嵌套结构 | 展开当前分支，保留上层位置感 |
| 参数影响 | 输入—机制—结果联动图 | 调整参数，立即观察结果及变化原因 |

- 图中的位置、方向、大小、颜色和连线应承载明确含义；必要时提供简短图例。
- 节点里放短标签，关系放在线上，详细说明放在选中后的局部视图。避免长段落塞进卡片再用箭头连接。
- 简单事实或精确查值可直接使用短句、数字或小表格，无需强行图形化。
- 图表保留单位、尺度和关键基准。缺失数据标明缺失；假设和演示数据明确标注，不编造实测结果。

## 让交互承担解释工作

每个控件都应回答一个具体问题，例如“这个因素影响谁”“条件改变后结果如何”“两个方案差在哪里”。无法说明理解收益的控件应删除。

- 优先让读者直接操作图中对象；全局控制仅保留最有解释力的少数项，其余按需出现。
- 输入与结果在同一视野中联动；明确显示当前参数、选中对象、结果和相关高亮，避免只改一个孤立数字。
- 悬停适合预览数值与短说明；重要细节也应支持点击或键盘聚焦。触屏不依赖悬停。
- 动画用于解释变化、方向和状态过渡；复杂过程可暂停、单步或重放。避免自动轮播、持续闪动和无意义动效。
- 控件标明用途及单位；用简短提示表达可操作性，例如“点击节点查看影响范围”。不要写大段操作手册。
- 计算模型说明必要假设；未经验证的模拟不可包装成真实预测。

例如：解释缓存流程时，默认展示请求路径与一句结论。读者切换“命中／未命中”，路径随之高亮；点击某一步才显示局部耗时与说明；计算口径置于可展开的证据区。

## 实现与交付

- 未指定交付方式时，优先生成可直接打开的独立 `.html` 文件，内联必要 CSS/JS。已有工程则遵循其结构；仅在复杂度需要时引入依赖，并说明联网或运行条件。
- 先设计信息层级与状态变化，再实现布局和代码。不要默认套用固定的仪表盘、卡片网格或营销落地页模板。
- 使用清晰的视觉主次、足够留白与适度强调。窄屏时可重排图和详情面板，避免靠缩小所有文字容纳大图。
- 交互入口支持键盘操作、可见焦点和合适的语义；选中与展开状态可被辅助技术感知。颜色之外也用标签、线型或形状表达差异，并尊重减少动态效果的偏好。
- 优先使用易于维护的 DOM/SVG。使用 Canvas 等渲染方案时，为关键信息提供可访问的等价内容。
- 提供 HTML 文件或可访问的页面链接，并简短说明主要探索入口；用户未要求时，无需在交付消息中复述整篇文档。

## 验收

交付前打开实际页面验证，而非只检查源码。使用当前环境可用的浏览器工具；若无法运行，明确说明未验证的部分，不宣称已通过。

- 不操作页面，能否直接看懂核心观点、主图含义和下一步入口？
- 每张图是否表达了关系或证据，每个控件是否改变了有意义的信息？
- 首屏是否出现过多同等醒目的内容，展开后是否仍只聚焦当前问题？
- 实际走通主要交互，检查默认、切换、展开、关闭和重置状态；验证图形、数值、标签和详情始终一致。
- 在窄屏与键盘操作下检查标签、控件、详情入口和返回路径；处理溢出、遮挡及运行错误。
- 复核结论、数据、必要限制和来源；精简表达不能牺牲事实准确性。
