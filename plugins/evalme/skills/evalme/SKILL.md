# EvalMe — 能力评测(一个入口)

系统闭环:**定目标 → 出题 → 练题留逐字稿 → 盲判打分 → 复盘看证据链**。
本 skill 是唯一入口,按用户意图路由到对应流程(phase);phase 文档在 `phases/`,按需读取再执行。

## 用户意图 → 流程

| 用户说… | 流程 | 读哪个文档 |
|---|---|---|
| "看看我现在什么水平 / 我该干嘛 / 进展怎么样" | 跑 `status`,把结果翻成大白话 | `phases/review.md`(要深入时) |
| "练一道题 / 模拟面试 / 来一场" | 练习:主持→逐字稿→入库→盲判→当场反馈 | `phases/practice.md` |
| "复盘 / 为什么是这个结论 / 下一步练什么" | assess → explain → next | `phases/review.md` |
| "出题 / 加题 / 贴一道真题 / 这段材料变成题 / 真实面试入库" | 出题(三来源,用户确认才入库) | `phases/create.md` |
| "打分 / 补打分 / 重判" | 盲判,逐 check | `phases/grade.md` |
| "定个目标 / 改目标 / 加个词 / 换机 / 归档" | 定标 + git 同步引导 | `phases/define.md` |

拿不准用户意图 → 先跑 `status`(见下),把"现在该干嘛"摆出来,再问他想做哪件。

## 公共协议(本入口统一讲,phase 文档不再重复)

- **数据位置**:goal home(`EVALME_HOME`,默认 `~/evalme/`)。CLI 自动选中唯一目标;多目标加 `--goal <id>`。与当前所在项目目录无关,任何目录直接可用。
- **脚本**:`<scripts>/evalme.mjs` = 本 SKILL.md 上两级(插件根)的 `scripts/` 目录,用 `node` 运行。
- **status(每次会话第一步)**:回答"现在该干嘛"——各领域档位健康度、待打分存货、缺题、建议动作。意图不明确时先跑它;之后无论哪个流程,会话结束有改动就跑一次 `sync --message "<摘要>"`。
- **同步**:会话动数据前 `sync --pull-only`(失败先解决,别在旧数据上写);会话结束有改动 `sync --message "<摘要>"`。读命令(assess/status/list)自动 freshen。无 git/无 remote 自动降级,单机零打扰。
- **共同纪律**:事实只增不改(纠错走 retract);结论必须有 transcript 行号证据;用户可见输出用档位和自然语言,不引用内部小数;LLM 永不直接产出健康度数字(引擎算)。

## 会话卫生(反锚定,全系统最重要)

- **会污染当前上下文的流程**:出题(create)、复盘(review)、打分(grade)——它们会让你见过 grader/参考答案/历史结论。
- **练习(practice)要求主持人 fresh context**:
  - 宿主支持交互式子代理(如 Pi)→ 子代理主持,本会话只当中继,上下文脏不脏无所谓(见 `phases/practice.md` 方式 A)。
  - 不支持子代理 → 本会话干净才可直接主持(方式 B);脏了就走交接(方式 C:给一句交接语,新会话说"练题"即可)。
- **打分(grade)永远 fresh context**:practice 结束后 spawn 盲判子代理;无法 spawn 时告知用户新会话说"打分"。
- 反锚定靠**上下文隔离**,不靠口头约定——隔离失效的流程宁可不做,也不能在脏上下文里硬做。

## 子代理调用形态

当本 skill 被作为子代理任务加载(如 practice 结束后 spawn 打分者),spawn 参数里带上
`skill: evalme`,任务文本写明要执行的流程(例如"执行 grade 流程,处理 trial <id>")。
此时**跳过路由**,直接读 `phases/<流程>.md`(相对本 SKILL.md 所在目录)照做,完成后只向
父会话回传结果摘要,不掺入父会话已有的任何判断。

## 开始

1. 用户意图明确 → 读对应 phase 文档,照流程执行。
2. 用户意图不明确 → 跑 `status`,把"现在该干嘛"翻成大白话,问他想做哪件。
