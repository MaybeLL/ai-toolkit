# EvalMe 复盘(我什么水平 → 为什么 → 下一步练什么)

读取侧三步:先刷新投影(assess,幂等、便宜),再看证据链(explain),最后选题(next)。
平时"看看我该干嘛"先跑 `status`(入口文档 §公共协议),这里承接深水区。

## 流程

1. **assess 先行**(读前必刷):注意输出的两类提醒——待打分存货(转告用户去打分)、题库没题可测的 topic(需要出题)。
2. **explain**:向用户转述时忠于引擎输出——
   - 用**档位**(weak/uneven/solid/strong)描述水平,**不要引用内部小数**当能力值;
   - **分层**是重点("没做过的场景 1/3 过,重复 3/3 过"——陌生场景才见真章);
   - **很久没验证**要点破("上次验证是 4 个月前,现在不确定了"),但只提醒,不自动排复测;
   - 每个结论给出 transcript 行号出处,用户质疑时带他看原文。
3. **next**:打印模式给出按优先级排序的 topic + 候选题(优先没做过的/变式)。把它包装成至多 3 条 action(`{topic, task_ref, reason}` 或 `{topic, create_needed: true, reason}`)从 stdin `--write` 写入 plan.json。
   - `mode: diagnose` = 证据不足,先做题探明,别急着"训练";
   - `create_needed` = 题库没合适的题,建议用户去出题;
   - 只排序 + 文字理由,**不编造"预计提升 +0.x"**。

## 红线

- 本流程不摄取(record/grade)、不制题、不改 goal.yaml。
- 数字全部来自引擎;你只解释和措辞,不修正、不脑补。
- 不向后续的练习/打分会话泄露本会话看到的结论(反锚定:主持人和判定者都必须是未被污染的上下文)。
