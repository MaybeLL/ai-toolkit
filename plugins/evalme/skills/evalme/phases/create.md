# EvalMe 出题(题面 + 预注册评分标准)

题库是系统的量具。一道题 = 题面(prompt)+ 预注册 grader(checks)+ labels + difficulty + 参考答案。

**三种来源:**

| 来源 | 场景 | grader 何时写 |
|---|---|---|
| `generated` | 按复盘缺口(create_needed)出新题 | 出题时,预注册 |
| `imported` | 用户上传题面(面经、真题、一段值得沉淀的材料) | 作答**前**补写,仍预注册 |
| `imported-live` | 真实面试已发生,从 transcript 反推 | 事后写,**非**预注册(自动降权) |

## 出题(generated)

1. 读复盘给的缺口(topic + mode);**不要读该 topic 的历史 transcript 细节**——按 topic 出题,不按用户的具体弱点反向定制题面(防 teaching-to-test)。
2. 写 check 的纪律:每条 = **条件 + 可观察行为 + 判别标准**,禁止形容词("清晰""熟练");问自己"强者和弱者在这条上会留下可从文本指认的不同行为吗?"。
3. 生成 reference_solution。
4. **质检**:模拟以判定者视角拿参考答案对照 checks,应全 pass;不能全 pass 说明题或 grader 有病,先修。
5. **可主持性质检**:题面明确区分共享背景与有顺序的问题;多个小问必须服务同一个能力判断,互不依赖的知识问拆成不同题;题面声明影响答案的系统契约;允许多种架构策略时,grader 接受"声明合理假设后作答"。
6. **展示草案并请求审批**:向用户展示题面、labels、difficulty、全部 checks 和 reference_solution,明确询问"是否确认将此 task 入库?"。
7. **用户明确确认后才入库**:只有用户明确同意这份具体草案,才执行 `task add` 并告知 task_ref。不要把"帮我出一道题"、继续对话或未回应当作确认;用户要求修改时,修订后重新请求确认。

## 导入(imported)

用户贴题面 → 你按词表标 labels、定 difficulty、起草 checks → **用户确认 grader** → 入库。确认必须发生在用户作答之前(预注册)。

## 材料抽题(imported 的变体:输入不是题面)

用户给的不是题,而是一段**值得沉淀的材料**——工作中踩过的坑、学习笔记里的精彩段落、一次技术讨论的结论。

1. **提炼考点**:这段材料真正考验的能力是什么?强者和弱者在这个点上会留下什么不同行为?(不是"背出这段话",而是"在新场景里用出这个判断")
2. **反推题面**:设计一个能自然诱出该考点的任务场景——优先选与材料原场景**不同**的业务背景(考迁移,不考复述);若考点属于已有题系的变式,标 `variant_of`。
3. **材料入 checks**:材料里的关键判断提炼成可指认的 check;材料本身可作为 reference_solution 的骨架。
4. label 不在词表时提醒用户:这可能是个新 topic,去定标流程加词(顺便定 weight)。
5. 后续同 imported:用户确认 grader → 入库。

这条路径是系统的低门槛进食口:材料随时可以抛进来变成题,哪天想练再练。

## 归一化(imported-live)

真实面试已发生:从 transcript 反推题面 → 起草 grader(用户确认)→ `origin: imported-live` 入库 → 告诉用户接下来走练习流程的 record(type=real_interview)再打分。

## 修订

task/grader 一经有判定引用即不可变;修订 = 新版本文件(version+1,CLI 强制版本连续)。修订后可对旧 trial 重判,聚合自动取最新版本判定。

## 红线

- label 不在词表 → 先去定标流程加词,不得私造。
- 不给练习泄 grader:出完题只交 task_ref;主持人只能 `task show --prompt-only`。
- 你不打分、不主持。制完即止。
