# EvalMe 练习(练一道题 → 当场反馈)

从题库取一道题,主持一场练习,存逐字稿、立即入库、盲判打分——一个闭环,用户当场拿到反馈,不留断链。

## 取题

- 单题:用户指定题,或从 `status`/`next` 的推荐里拿。
- 整场模拟:`exam --size N` 组卷(按 topic 权重轮转、优先没做过的题,建议 session_id 一并给出),按卷面顺序主持,全场共享 session。
- 主持人**只看题面**:`task show <ref> --prompt-only`,绝不看 checks。`exam` 输出不含 checks,可安全使用。

## 主持方式(三档,按宿主能力选)

### A. 子代理主持(首选:免切换会话,上下文脏不脏都行)

宿主能 spawn 交互式子代理(如 Pi 的 contact_supervisor 机制)时,本会话只当中继:

1. 取好 task_ref 后,**spawn 一个 fresh-context 面试官子代理**。任务里只给:goal home(让子代理自动解析)、task_ref、
   面试官规则(逐问披露、每轮一主问 + 至多一中立追问、不评价不教学、用户要提示时记 hints、结束写逐字稿文件并回传路径)。
   面试官自己 `task show --prompt-only` 取题面——**本会话不看题面也不看 checks**。
2. 面试官通过「向父会话提问并等待」的机制逐问推进;本会话把它的问题**原文转述**给用户,
   把用户回答**逐字转发**回子代理(不改写、不压缩、不润色);用户要提示,也原样转给面试官决定。
3. 面试官写完逐字稿、回传路径后:本会话立即 `record`,再 spawn 盲判子代理(见 `grade.md`),当场给反馈。

**本会话的中继是机械的**:不解释、不点评、不补充、不暗示——哪怕你上下文里见过 checks,也一个字都不能带进转述。

### B. 本会话主持(宿主无交互式子代理,且本会话干净)

当前上下文只要看过 grader、reference_solution、历史 grading/assess 结论,
或刚执行过出题/打分/复盘流程,就不得主持——立即停止,走 C 交接。
干净则按下面"主持纪律"直接主持。

### C. 交接(本会话脏,或子代理主持不可用)

给用户一句交接语,只含:goal、task_ref(如"新会话说:练题,goal=backend,task=payment-system-v1")。
**不带任何题面、答案、checks 内容。**

## 主持纪律(方式 A、B 都守)

- 先读完整 prompt 仅用于内部拆分,识别「所有后续回答都需要的共享背景」与「依次作答的问题」。
  首轮把共享背景和**第一个问题**写给用户。
- **每个 assistant 回合最多只提出一个主问题**,不得提前展示后续问题。多 part、多小问也逐个推进,不因同属一道题就整包抛出。
- CLI/tool 输出不等于用户可见的主持话术。共享背景与当前问题**必须写进 assistant 正文**,禁止用"如上""见工具输出"代替。已给过的长背景无需每轮重复,只补当前问题所需材料。
- 用户回答当前问题后,最多进行一个中立追问;追问结束再进入下一问。中立追问只要求澄清假设、作出单一选择、补全理由或分析取舍,
  **不得确认答案正确、暗示目标动作、指出缺失知识点、替用户排除选项**,也不得使用"不错""这个边界你掌握了""这不行"等评价语言。
- 用户主动要提示可以给并记 `--hints true`;主持人意外做了方向性提示或泄露答案,即使用户没要求,**也必须记 `--hints true`**——不能继续声称本场"无提示"。
- 像真实面试官一样保持中立,不评价、不教学。同场多题共享一个 `--session`;多题场次散场前不披露任何判定结果(中途报分会无意识照顾弱点、打断状态)。

## 存稿与入库

- 逐字、中立的逐字稿写入 `transcripts/<日期>-<题系>.md`。只记发生了什么,不写任何评语——评价属于打分层。
- **立即 `record`**:conditions 如实填(是否限时/提示/查资料,包括主持人意外给出的提示);`--type` 按实际选(mock_interview / practice / real_interview);真实面试(用户贴稿,题已由 create 归一化)也走这里,`--type real_interview`。
- 记错了(conditions 填错、逐字稿贴错)→ `retract` + 重新 `record`。事实不可改,只可撤销重录。

## 即时盲判

record 后 spawn 一个 **fresh-context 子代理**执行打分流程,**只传 trial_id**——不传你对这场练习的任何印象、评语、摘要(trial_id 是不携带判断的指针;子代理自行从 CLI 打印模式取冻结材料,数据位置由 goal home 自动解析)。
spawn 时给子代理加载本 skill(`skill: evalme`),任务只写:"执行 grade 流程,处理 trial <id>"——子代理会读 `phases/grade.md`(相对本 SKILL.md 所在目录)照做,并向父会话只回"已落库"+ 判定 id 清单。
无法 spawn 子代理时退回:告知用户新会话说"打分"。

## 红线

- 绝不 `task show` 全量(只许 `--prompt-only`)。
- 看过 grader/reference_solution/历史结论的上下文绝不主持——除非走方式 A,主持人(子代理)本身是 fresh 的。
- 一次只问一个主问题,一次回答最多一个中立追问;不提前展示后续问题。
- 逐字稿中不夹带你的评价。
- 本会话永不自行执行 grade 的判定步骤——你主持过,已被污染;只能 spawn fresh-context 子代理去判(反锚定靠上下文隔离,不靠时间隔离)。
- spawn 时只传 trial_id,不传印象;多题场次散场前不披露任何判定结果。
