# 视频下载

用现有 yt-dlp CLI 完成用户要求的下载，交付实际文件及验证结果。Skill 不代表 CLI 已安装，也不代表某个站点已经实测可用。

## 检查依赖 → 确认安装 → 复查

1. 下载前先按 [依赖检查与安装](references/dependencies.md) 检查当前任务的工具。可运行包内 [只读检查脚本](scripts/check_dependencies.py)：`python3 <skill目录>/scripts/check_dependencies.py --mode video`；音频用 `audio`，仅字幕用 `subtitles`，YouTube 加 `--youtube`。没有 Python 时按参考文档手动检查，不为运行检查器先安装 Python。
2. 将结果分为可用、缺失、不可用和待核实；命令不在 PATH 不等于机器上未安装，先排查已知安装位置与配置。未知项不得当成缺失项直接重装。依赖齐全则继续任务，不询问安装。
3. 发现本次需要的缺失项后，说明名称、用途、安装来源/方式及是否需要管理员权限，一次性询问用户是否安装这些具体项。没有确认就暂停依赖这些工具的步骤，不执行安装或升级。已有对相同安装方案的明确确认可复用；普通下载请求不视为安装许可。
4. 用户确认后，由 agent 按参考文档执行缺失项的安装，复用现有包管理器和安装环境。用户拒绝时，说明受影响能力；只有不影响其目标的降级方案才可继续，不把未验证的媒体称为完整交付。
5. 安装后重新运行相同检查；PATH 未刷新则用已核实的绝对路径验证，再继续原下载任务。安装命令成功不等于工具可用，依赖检查成功也不等于视频已下载。

## 范围与配置

- 检查 yt-dlp 生效配置的位置与影响，不输出其中的 Cookie、代理凭据等敏感值。保留已有配置，用本次命令参数覆盖需要调整的选项；只有用户要求持久配置时才修改配置文件。
- 只下载用户指定的视频或集合。普通单视频默认加 `--no-playlist`；完整播放列表、合集、全部分 P、频道或直播录制必须来自用户意图。遇到多条结果时检查范围，不能假设 `--no-playlist` 能阻止所有站点的集合展开。
- 优先使用用户指定目录，其次沿用有效的现有下载目录；都没有时使用 `~/Downloads/Videos`，转换为绝对路径后创建。默认选择当前账号可访问的最佳质量，不承诺未登录也能下载高清或会员画质。

## 下载流程

1. 从分享文本提取 HTTP(S) 链接，保留必要查询参数，支持 b23.tv 等短链。URL 和文件名作为数据传入参数数组；使用 shell 时正确引用，并在 URL 前使用 `--`。不要将用户分享文本拼成可执行代码。
2. 用下列元数据命令识别标题、站点、时长、视频 ID、是否直播及返回范围。只输出这些必要字段，不展示完整 JSON 中可能出现的带签名媒体地址。用户指定分辨率、编码或格式时再运行 `-F` 查看可用格式。

   ```bash
   yt-dlp --no-playlist --skip-download --dump-single-json -- "视频链接"
   yt-dlp --no-playlist -F -- "视频链接"
   ```

3. 确认是普通点播且范围正确后下载。以下为基础命令，替换目录与链接；已有配置若启用了额外下载行为，应针对本次调用覆盖。默认保留断点文件，避免覆盖已存在的成品。不为一次下载修改全局代理或网络设置。

   ```bash
   yt-dlp --no-playlist --no-overwrites \
     -P "/绝对路径/下载目录" \
     -o "%(title).180B [%(id)s].%(ext)s" \
     --print after_move:filepath -- "视频链接"
   ```

   保留正常进度和错误信息。长下载使用可轮询的进程会话，按实际进展更新用户。以合并/移动后的路径定位成品，不猜测扩展名，不把 `.part` 当成视频。

4. 验证命令退出状态、成品存在且非空，再检查媒体：

   ```bash
   ffprobe -v error \
     -show_entries format=duration,size:stream=codec_type,codec_name,width,height \
     -of json "/绝对路径/成品文件"
   ```

   视频任务应有视频流；源视频有音轨且用户没有要求静音时，还应有音频流。核对时长与元数据是否合理一致。必要时对异常文件做解码检查。仅 ffprobe 成功只能称“媒体结构检查通过”，不能称“已完整播放验证”。
5. 交付文件链接、实际画质/时长、大小和必要限制。批量任务分别报告成功、跳过、失败数量；“已存在”或归档跳过不算本次新下载，已有文件仍需检查。失败时准确说明已完成的部分和具体阻塞，不能将提取元数据成功当作下载成功。

## 按用户需求调整

- **限制最高 1080p**：`-f "bv*[height<=1080]+ba/b[height<=1080]"`。没有匹配格式时解释并选择用户可接受的降级，不悄悄下载更高分辨率。
- **仅音频**：`-x`；明确要求 MP3 时使用 `-x --audio-format mp3`，需要 FFmpeg。
- **仅字幕**：`--skip-download --write-subs --sub-langs "zh.*,en.*"`，按用户语言要求调整；自动字幕需加 `--write-auto-subs` 并说明其性质。检查实际生成字幕文件；退出码为零不代表存在所需字幕。
- **批量/列表**：用户明确要求后使用 `-a URL文件` 或播放列表链接；按需求加 `--playlist-items`，对持续增量下载可使用任务专属 `--download-archive`。不要默认遍历整个账号或频道。
- **MP4**：`--merge-output-format mp4` 只影响合并容器，不保证所有结果转为 MP4，也不保证播放器支持内部编码。优先选兼容的 H.264/AAC 流；重封装和有损转码应根据用户格式要求决定并解释成本。
- **登录后可见内容/高清**：先尝试公开访问。确实需要登录时说明原因，取得用户对本地浏览器登录状态的使用授权后，使用 `--cookies-from-browser 浏览器名`。不要让用户在聊天粘贴 Cookie，也不要把 Cookie 写入 Skill、日志或仓库；账号仍需有对应访问权限。

## 故障处理与边界

- 网络超时先区分 DNS、TLS、下载源和视频站点连通性；用有限超时的只读请求检查。必要时尝试本次进程的 `--force-ipv4`，不要直接更改系统 DNS、VPN、Tailscale 出口或防火墙。
- 同一路径连续失败后换有依据的路径，不无限重试。安装源故障可使用官方发行文件或可信镜像并校验哈希；不关闭 TLS 验证。多条路径都失败时报告阻塞；若确需改变整机外网出口，说明影响并取得单独授权。
- 403、412、429 等先考虑登录、频率限制和站点变动。限制重试，适当退避；不要为风控问题增加并发或反复读取浏览器凭据。只有证据指向提取器问题时才升级并重试。
- 遇到会员权限、地区限制、DRM 或账号权限阻塞，说明具体限制，不承诺通过换参数绕过。
- 不将某台机器过去的失败或安装状态写成永久事实。每次重新检查；B 站成功仅证明该 B 站链接，不能外推为 YouTube 或所有视频均可用。
