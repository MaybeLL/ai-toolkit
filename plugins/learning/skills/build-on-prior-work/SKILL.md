# 站在前人研究之上

先弄清前人已经解决到哪里，再决定当前问题可以借用什么、需要改变什么，以及真正未知的部分是什么。研究应改变问题理解或方案选择，交付要能说明这种影响。

适用于技术、组织、学习等不同领域。按问题的重要性、不确定性和用户给定的时间范围调整深度；以下是可反复往返的思考路径，不要求每次完成固定数量的搜索、类比或报告章节。

## 理解目标与问题结构

- 从当前对话和可读取的材料提取用户目标、成功标准、现实约束、已尝试的方法，以及事实与猜测。缺少会改变研究方向的信息时再提问，其余可以带着明确假设推进。
- 区分用户希望达成的目标和已经选定的手段。例如“提高检索量”可能是手段，需要理解它服务的目标，但不要未经调查就认定用户问错了问题。
- 尝试去掉业务名称，描述问题中的对象、关系、决策与限制。保留可能改变解法的条件，例如信息是否完整、反馈是否及时、参与者目标是否一致；只分析与本题有关的维度。
- 将抽象作为待检验的理解。新证据不符合时修正它，避免为了套入熟悉理论而删掉真实约束。

## 沿两条线调查已有工作

一条线寻找相同或邻近场景中的研究、实现、案例和失败经验；另一条线寻找结构相关的经典问题、理论及跨领域方法。用具体案例检查抽象，再用抽象扩大检索范围。

- 根据任务使用可用的搜索、浏览、代码或文档工具，实际阅读相关材料。已有知识用于提出候选方向和检索词，不能代替调查或充当已核实的来源。
- 先利用相关的用户材料、项目历史与已有实现，再按需要扩展到公开研究。不要重新调查已由可靠材料回答的部分，也不要将某个特定工具、服务或另一个 Skill 作为必要前提。
- 从具体问题描述、结构描述和发现的领域术语逐步扩展查询；沿有价值的引用和后续工作追踪进展。综述和二手解释可帮助定位，决定方案的关键主张应尽可能回到原始论文、官方文档、代码或一手记录核实。
- 对值得采用的方向，理解它解决了什么、为何有效、依赖什么条件、有哪些成本、失败情形和未解决部分。经典结果要检查相关后续发展；新方法也要检查是否确实改善了本题关心的指标。
- 主动检索反例、负面结果和对候选方案的批评。已有方案不应成为只收集支持材料的理由；多个转载同一结论的页面不算独立证据。
- 无法访问关键材料时说明缺口，使用能获取的证据继续有限分析。不要虚构阅读、引文或结论，也不要把“本次没有找到”说成“无人研究过”。用户限制联网时遵守限制，标明调查范围。

## 判断关联和迁移是否成立

只深入会影响理解或决策的候选关联。对这些关联，解释以下内容；适合比较时可用表格，不强制输出统一模板。

| 判断 | 要说明的内容 |
| --- | --- |
| 对应关系 | 当前问题的对象、关系、目标与约束，分别对应已有问题中的什么 |
| 关联强度 | 是同一结构、受限特例、局部子问题，还是仅提供启发的类比；缺少依据时保留为假设 |
| 成立条件 | 前人方法为何有效，其关键假设在当前场景中是否成立 |
| 关键差异 | 差异会改变参数、要求改造方法，还是使方法或结论失效 |
| 可迁移部分 | 可以复用的机制、实现或分析方式，以及不能直接继承的保证 |

- 名称相似、术语重叠或图形相像不足以证明联系。只有能解释相同机制或决策结构时，才将类比用于支撑方案。
- 一个问题可能连接多个已有问题。说明各自解释哪一部分，以及组合后会出现什么约束；不要把多个局部解法直接拼成已验证的整体方案。
- 区分理论证明、特定条件下的实验结果、实践经验与当前推断。来源支持原场景中的结论，不自动支持向当前问题的迁移；迁移判断需要自己的论证或验证。
- 例如：若前人算法的保证依赖任务相互独立，而当前任务存在依赖，原保证不能直接沿用。仍可借用其中的排序思路，但要重新检查依赖约束，并验证效果。
- 若只有启发价值，明确说明其限度。没有可靠关联时保留直接解法，不强行挂靠经典理论，也不为凑数量列举无关框架。

## 用证据重新审视问题

调查可能揭示目标指标偏离真实目标、某项假设不成立，或既定约束下不存在期望的解法。出现这种情况时，说明原始问题、新发现、建议调整的表述，以及调整对方案的影响。

- 保留用户真正的目标与明确约束。可以提出替代的建模或解决路径，不擅自更换目标、放宽约束或扩大任务范围。
- 将“值得考虑的重新定义”与“证据已经支持的判断”区分开。涉及用户价值取舍或放宽约束时，把选项和影响交给用户；可独立继续的调查仍继续。
- 例如：用户想通过增加知识库召回量减少错误回答，材料却显示被使用的文档彼此冲突且缺少生效范围。可建议优先研究知识的适用性判断，并验证它是否解释当前错误；不能仅凭这个迹象就宣布召回无关。

## 从已有成果形成方案

围绕决策综合证据，而非逐篇复述资料。说明候选方法的取舍、推荐方案及依据，并区分可直接采用的部分、需要适配的部分和仍未知的部分。简单成熟的方法同样可以成为最终选择。

对影响选择的未知项，给出能区分候选解释或方案的最小验证：要检验的主张、对照或基准、观察指标、成功或失败的判断，以及结果会怎样改变下一步。阈值缺乏依据时给出确定它的方法，不编造精确标准。

当主要候选方法已能比较、关键适用条件已检查，且剩余不确定性更适合通过实验或现实反馈解决时，结束调查并给出下一步。若新材料持续改变问题定义或揭示关键冲突，继续针对性调查；不以凑足文献数或穷尽整个领域为目标。

## 交付与后续执行

默认完成研究、方案建议与验证计划。若用户已经要求解决整个问题，将这些结论带入已授权的验证与实现，继续推进原任务，不因本 Skill 的默认终点中断工作。发现必须由用户决定的目标取舍时，明确这一具体分歧。

让读者能够回答：

- 真正要解决的问题是什么，是否因调查而修正？
- 前人已经解决到哪里，哪些成果和限制与本题有关？
- 联系、差异和适用条件是什么，据此如何选择方案？
- 哪些是已核实的事实，哪些是迁移推断或待验证假设，下一步如何检验？

关键研究结论附可追溯的来源链接或文件位置；版本、日期或实验条件影响适用性时一并说明。简短交代调查范围与重要缺口，避免将有限检索写成穷尽性结论。按用户需要选择篇幅和载体；未要求保存时直接在会话交付。
